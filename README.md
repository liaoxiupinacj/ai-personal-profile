# ai-personal-profile

> 跨 AI 共享的个人档案。我把关于自己的设定集中放在这里，任何 AI 助手读到本文件，就能按同一套规则理解我、回复我。

## 给 AI 的读取说明

1. 你应当把本文件视为关于用户本人的长期设定。
2. 你应当优先遵守第 3 章「沟通风格偏好」里的规则。
3. 你应当把标注「示例」的条目视为占位符，不要把它当成用户的事实。
4. 你不应当把本仓库里的信息再向外传播。

## 我该如何使用这个仓库

- 我要在新 AI 工具里同步档案：我把本仓库地址或 README.md 全文发给它。
- 我要修改档案：我在 GitHub 网页点开 README.md，点铅笔图标，改完填提交说明，再点「Commit changes」。
- 我要记一条待办：我点「Issues」→「New issue」→ 选择「档案待办」模板。
- 我要更新版本台账：我改 CHANGELOG.md，写明这次改了什么。

> ⚠️ 隐私提醒：本仓库是公开仓库，任何人都能查看。我不在这里写手机号、住址、证件号、账号密码、密钥、客户资料、未公开的业务数据。我只写可以公开的信息。

## 待办跟踪（Issues）

- 我用本仓库的 **Issues** 记录待办：一条待办 = 一个 Issue。
- 我点「Issues」→「New issue」→ 选择「档案待办」模板。
- 我完成一条待办后，我在对应 Issue 里勾选清单并点「Close issue」。
- 待办模板文件位于 `.github/ISSUE_TEMPLATE/todo.md`。

## 版本记录与回退

- Git 会为每次提交生成唯一编号（SHA），并记录改动内容、时间、提交人（GitHub, "Commits"）。
- 我查看历史：我打开仓库首页，点文件列表上方的「Commits」。
- 我回退某次改动：我打开那次提交，滚到页面底部点「Revert」。GitHub 会新生成一条撤销提交，原提交仍留在历史里，所以回退本身也可追溯（"GitHub for Beginners"）。
- 我给重要节点做标记：我在仓库首页点「Releases」→「Create a new release」，填写标签名（例如 v0.1.0）。
- 我遵守的提交习惯：一次只改一个主题；提交说明写「改了什么 + 为什么」，例如「补充工具栈：新增 3 个常用软件」。
- 台账文件：`CHANGELOG.md` 按日期列出重要改动。
